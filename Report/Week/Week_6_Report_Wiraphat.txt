        ต่อมาวิเคราะห์ปัญหาที่ระบบไม่เข้าสู่โหมด Idle หลังเวลา 22:00 น. ทั้งที่ Config กำหนด ACTIVE_WINDOWS ไว้เป็น 05:00 ถึง 22:00 พบสาเหตุที่ stream_server.py บรรทัด 863 ซึ่งปุ่ม START ใน Web UI Spawn main.py ด้วย Environment Variable FACE_ALWAYS_ACTIVE='1' ซึ่งเคยเป็น Workaround ของสัปดาห์ที่ 5 สำหรับโหมด Headless ทำให้ main.py Bypass การตรวจสอบ Active Window ตลอดเวลาและรัน 24 ชั่วโมงไม่เคยเข้าสู่ Idle ได้แก้ไขโดยลบ Environment Variable นี้ออกจาก dict ทำให้ main.py กลับมาเคารพ ACTIVE_WINDOWS ใน config.py ตามปกติ

        จากนั้นปรับปรุง UI ในส่วน Last Seen และ TodayCard ให้ดึงรูปจาก External API แทนไฟล์ที่เก็บในเครื่อง โดยเพิ่ม Endpoint /person/{per_id} ใน api.py ที่เรียก fetch_person_by_pid() และส่งคืน per_picpath ซึ่งเป็น URL รูปภาพจาก External API เพิ่ม Proxy Rule /person ใน vite.config.js และเพิ่มฟังก์ชัน fetchPerson(perId) ใน attendance.js ส่วน LiveCam PersonPanelCard เพิ่มแสดง last_seen ใต้ first_seen และเปลี่ยนแหล่งรูปเป็น per_picpath พร้อม Fallback เป็นตัวอักษรแรกของชื่อถ้าไม่มีรูป สำหรับ Dashboard TodayCard ได้ Restructure ให้รวม IN และ OUT ของบุคคลเดียวกันเป็นการ์ดเดียวกัน แสดง 2 แถวคือเวลา IN พร้อมชื่อกล้องที่ใช้ และเวลา OUT พร้อมชื่อกล้อง โดย Group ด้วย useMemo และเรียงตามเวลาล่าสุด

        นอกจากนี้ยังได้ดำเนินการ Mask per_id ทั้งระบบเนื่องจากผู้ใช้สังเกตว่ารูปที่บันทึกลงเครื่อง (live_snap และ PicSAVE) ใช้ per_id ครบ 13 หลักเป็นชื่อไฟล์ ซึ่งเป็นความเสี่ยงด้านข้อมูลส่วนบุคคล ได้เพิ่มฟังก์ชัน mask_pid() ใน api_client.py (Python) และ maskPid() ใน utils/pid.js (JavaScript) ที่แปลง "6666666666666" เป็น "*********6666" แล้วนำไปใช้ในชื่อไฟล์ live_snap, live_snapfull, PicSAVE, ชื่อ Key ใน State ที่ส่งให้ Frontend, Panel UI ใน ui_renderer.py, รวมถึงการแสดงผลใน Dashboard TodayCard โดยยังคงเก็บ per_id เต็มไว้เฉพาะในฟิลด์ per_id ของ State JSON เพื่อใช้ Lookup รูปผ่าน Endpoint /person/{per_id}

        ช่วงท้ายของวัน ผู้ใช้รายงานว่าเมื่อลงชื่อเข้าที่กล้องหนึ่งแล้วออกที่อีกกล้อง ระบบกลับบันทึกไฟล์ใน PicSAVE เป็น "_IN.jpg" ทั้งสองใบ แทนที่จะเป็น IN และ OUT วิเคราะห์พบว่าแต่ละกล้องมี SessionManager แยกกัน และฟังก์ชัน try_checkin ไม่ได้ตรวจสอบ Return Value ของ mark_attendance เลย จึงเซ็ต person.checked_in=True เสมอ ทำให้ save_snapshots บันทึก _IN.jpg ทุกกล้องที่เห็นหน้า ได้แก้ไข 2 ชั้น คือเปลี่ยน Return Type ของ mark_attendance จาก bool เป็น Tuple (ok, reason) เพื่อแยกสาเหตุการปฏิเสธจาก DB กับ Network Error และใน try_checkin เมื่อพบว่า reason คือ "IN แล้ว" (มาจากกล้องอื่น) จะเซ็ต is_out_cam=True แล้วย้าย snapshot ไปเป็น snapshot_out สำหรับบันทึกเป็น _OUT.jpg แทน

        ผู้ใช้ถามต่อว่าหากมีกล้องมากกว่า 2 ตัว (3 ตัวขึ้นไป) ระบบยังทำงานถูกต้องหรือไม่ ได้วิเคราะห์พบว่ายังมี Bug 2 จุดในกรณี N กล้อง คือกล้องกลางระหว่าง IN-Cam และ OUT-Cam จะบันทึก _OUT.jpg ด้วยเพราะ is_out_cam=True ทั้งหมด และการ Race Condition ตอน do_checkout เวลา 22:00 ที่ทุกกล้องเรียก mark_attendance("OUT") พร้อมกันทำให้ DB ได้เวลา OUT จากกล้องที่อาจไม่ใช่กล้องสุดท้ายจริง ได้แก้ไขโดยเพิ่ม Flag in_success และ out_success ใน PersonInfo ซึ่งจะเป็น True ก็ต่อเมื่อกล้องนั้นชนะ Race ใน DB จริง และ save_snapshots จะบันทึก _IN.jpg เฉพาะกล้องที่ in_success=True และบันทึก _OUT.jpg เฉพาะกล้องที่ out_success=True ส่วน Race Condition ใน do_checkout ใช้วิธี Delay-based Resolver คำนวณจาก stale_sec = now - last_detected_ts แล้ว time.sleep(min(stale_sec/1800, 60)) ทำให้กล้องที่เจอล่าสุด Sleep น้อยที่สุดและชนะ Race เป็นกล้อง OUT จริง

ปัญหาและอุปสรรค์ที่พบ

  - CSS Classes ที่ JSX อ้างอิงไม่มีในไฟล์ index.css ทำให้ Discord Mode และ @keyframes ต่างๆ พังทั้งหมด
  - ภาพจากกล้องค้างหลังกด Stop เพราะ img Tag ไม่ได้ Unmount ออกจาก DOM
  - Endpoint GET /state/{cam_id} ถูกเรียกทุก 1 วินาทีตลอดเวลาแม้ระบบ Stop แล้ว
  - Daemon Threads ถูก Kill ก่อนที่ save_snapshots() จะทำงานเสร็จในโหมด Headless
  - การ Pull โปรแกรมจาก Docker Hub ขาดส่วนสำคัญ เช่น ไฟล์ .env และ Query การสร้าง DB
  - การตั้งค่า IP Camera และ Protocol ใน .env ผิดพลาดทำให้เชื่อมต่อกล้องไม่ได้
  - โปรแกรมไม่เข้าสู่โหมด Sleep/Idle เมื่อถึงเวลาที่กำหนดใน Config เพราะ FACE_ALWAYS_ACTIVE=1 ถูก Inject ตอน Spawn
  - Frontend ไม่เคยตรวจสอบ state.idle ทำให้แสดง Badge LIVE ทั้งที่หลังบ้าน Idle อยู่
  - last_seen มีใน State ของ Backend แต่ไม่เคยถูกนำมาแสดงผลใน UI
  - isFresh() Threshold 5 วินาทีตึงเกินไปสำหรับโหมด Headless ที่มี Latency จาก Disk I/O
  - ชื่อไฟล์รูปที่บันทึกลงเครื่อง (live_snap และ PicSAVE) ใช้ per_id ครบ 13 หลักเป็นความเสี่ยงข้อมูลส่วนบุคคล
  - PicSAVE บันทึก _IN.jpg ซ้ำทุกกล้องที่เห็นหน้า เพราะ try_checkin ไม่ตรวจ Return ของ mark_attendance
  - กรณี N กล้อง กล้องกลางระหว่าง IN และ OUT จะบันทึก _OUT.jpg เกินจริง และมี Race Condition ตอน do_checkout
