# 🖥️ คู่มือ: ทำ Desktop ออฟฟิศให้เป็น VPS (สำหรับ OpenMPTCProuter)

**สำหรับ:** Desktop Linux ที่ออฟฟิศ + True Internet 100/100 + Public IP

**ผลลัพธ์ที่ได้:** Desktop ของคุณจะกลายเป็น "Server กลาง" ที่ Pi 4 (ที่ site ห่างไกล) เชื่อมเข้ามา + Remote client ทั่วโลกเชื่อม WireGuard เข้ามาได้

**เวลาที่ใช้:** 3-5 ชั่วโมง

---

## 🎯 VPS คืออะไร และเรากำลังทำอะไร

**VPS (Virtual Private Server)** = เครื่อง server ที่เชื่อมต่อ Internet ตลอดเวลา มี Public IP ที่เครื่องอื่นเข้าถึงได้

**Cloud VPS ทั่วไป** = เช่าจาก AWS/Vultr/DigitalOcean → จ่ายรายเดือน

**Self-hosted VPS** = เอาเครื่องคอมเองมาทำเอง → ฟรี แต่ต้องเปิด 24/7

**สิ่งที่ทำให้เครื่องคอมกลายเป็น VPS ได้:**

| ปัจจัย | ของคุณ | สถานะ |
|---|---|---|
| Public IP | ✅ มี (True Office) | ผ่าน |
| Internet 24/7 | ✅ มี | ผ่าน |
| ฮาร์ดแวร์เพียงพอ | ✅ มี | ผ่าน |
| OS ที่ถูกต้อง | ⚠️ ต้องเช็ค | ต้องเตรียม |
| Port forwarding | ⚠️ ต้องตั้ง | ต้องเตรียม |
| Firewall | ⚠️ ต้องตั้ง | ต้องเตรียม |

---

## ⚠️ คำเตือนก่อนเริ่ม — อ่านให้ละเอียด!

OMR install script จะ:
- 🔴 **ลง custom kernel ใหม่ทับ kernel เดิม** — ระบบเปลี่ยน
- 🔴 **เปลี่ยน firewall rules ทั้งหมด** — ระบบ network เปลี่ยน
- 🔴 **เปิด services หลายตัว** (Glorytun, Shadowsocks, MLVPN, OpenVPN) — ใช้ RAM/CPU
- 🔴 **เปลี่ยน SSH port จาก 22 → 65222**
- 🔴 **อาจ conflict กับ services อื่นที่ใช้ port 65xxx**

**❗ ผมขอแนะนำว่า:**

✅ **ดีที่สุด:** ลง Linux ใหม่ทั้งเครื่อง dedicated สำหรับงานนี้
✅ **รองลงมา:** ใช้ VM (VirtualBox/Proxmox) แยกต่างหาก
⚠️ **เสี่ยง:** ลงทับเครื่องที่ใช้งานประจำวัน

ถ้าเครื่องนี้มีข้อมูลสำคัญ → **Backup ก่อน!**

## 🛠️ Phase 0: ตัดสินใจวิธีติดตั้ง

เลือก 1 ใน 3 วิธี:

### วิธี A: ลง Linux ใหม่ทั้งเครื่อง (แนะนำที่สุด)

**ข้อดี:** สะอาด, ไม่มี conflict, เร็ว
**ข้อเสีย:** ข้อมูลเก่าหาย (ต้อง backup ก่อน)

### วิธี B: ใช้ VM (Virtual Machine)

**ข้อดี:** เครื่องเดิมไม่กระทบ, แยก isolated
**ข้อเสีย:** Performance ต่ำกว่า ~10-15%, ตั้ง bridge network ยุ่ง

### วิธี C: ลงบน OS เดิม

**ข้อดี:** ไม่ต้องลง OS ใหม่
**ข้อเสีย:** เสี่ยงเครื่องพัง, conflict กับ apps อื่น

## 💾 Phase 1: ลง Ubuntu Server (เตรียม OS)

### 1.1 Backup ข้อมูลสำคัญจาก Desktop เดิม

ก่อนทำอะไร — copy ไฟล์สำคัญออกจาก Desktop:

```bash
# เสียบ external HDD/USB → คัดลอกข้อมูลสำคัญทั้งหมด
cp -r /home/<username>/Documents /media/<external-drive>/
cp -r /home/<username>/Pictures /media/<external-drive>/
# ฯลฯ
```

หรือใช้วิธีง่ายๆ ลาก-วางผ่าน file manager

### 1.2 Download Ubuntu Server 24.04 LTS

ที่คอมหลักของคุณ (notebook):

ไปที่: **https://ubuntu.com/download/server**

Download: `ubuntu-24.04.x-live-server-amd64.iso` (~3GB)

⚠️ **เลือก "Server" ไม่ใช่ "Desktop"** เพราะ:
- ใช้ RAM น้อยกว่า
- ไม่มี GUI ที่ไม่จำเป็น
- เสถียรกว่าสำหรับ server

### 1.3 สร้าง Bootable USB

**ต้องการ:** USB drive 8GB+ (ข้อมูลใน USB จะหายหมด)

**Software ที่ใช้สร้าง USB Boot:**
- **Windows:** Rufus → https://rufus.ie/
- **macOS:** Balena Etcher → https://etcher.balena.io/
- **Linux:** Balena Etcher หรือ `dd` command

**ขั้นตอน (Rufus บน Windows):**
1. เสียบ USB drive
2. เปิด Rufus
3. Device: เลือก USB
4. Boot selection: เลือกไฟล์ ISO ที่ download มา
5. Partition scheme: GPT (สำหรับเครื่องใหม่) หรือ MBR (เครื่องเก่า)
6. Click START → รอ 5-10 นาที

### 1.4 Boot Desktop จาก USB

1. เสียบ USB เข้า Desktop ออฟฟิศ
2. เปิดเครื่อง → กด **F2/F12/DEL/ESC** (แล้วแต่รุ่น) เพื่อเข้า BIOS
3. ใน BIOS:
   - Boot menu → เลือก USB
   - หรือ Boot Order → ตั้ง USB ก่อน HDD
4. Save & Exit
5. เครื่องจะ boot จาก USB → ขึ้น Ubuntu installer

### 1.5 ติดตั้ง Ubuntu Server

หน้าจอ installer (ใช้ลูกศร + Tab + Enter):

- เลือก English (ภาษาไทยยังไม่ stable บน server)

**Step 2: Keyboard**
- Layout: English (US)

**Step 3: Type of install**
- เลือก "Ubuntu Server" (ไม่ใช่ minimized)

**Step 4: Network**
- ระบบจะหา network adapter อัตโนมัติ
- ถ้า Ethernet ต่ออยู่ → จะได้ IP จาก DHCP
- **จดเลข IP ที่ได้!** เช่น `192.168.1.50`

**Step 5: Proxy**
- ปล่อยว่าง (ไม่ต้องใส่)

**Step 6: Mirror**
- ค่า default ใช้ได้ (Ubuntu auto-detect)

**Step 7: Storage**
- เลือก "Use entire disk" → "Done"
- ⚠️ ข้อมูลใน HDD จะหายทั้งหมด!
- Confirm: "Continue"

**Step 8: Profile setup**
```

Server's name:    omr-server (หรือชื่อที่ชอบ)
Username:         ใส่ username (จดไว้!)
Password:         ใส่ password ที่จำได้ (จดไว้!)
```

**Step 9: SSH Setup**
- ✅ **ติ๊ก "Install OpenSSH server"**  ← สำคัญมาก!
- Import SSH key: ข้าม (No)

**Step 10: Featured Server Snaps**
- ไม่ต้องเลือกอะไร → "Done"

**Step 11: Install**
- รอ 10-20 นาที
- เมื่อเสร็จขึ้น "Reboot Now"
- **ถอด USB drive ก่อน reboot!**

### 1.6 First Login

หลัง reboot จะขึ้นหน้า login ดำๆ:
```
omr-server login: <username>
Password: <password>
```

ถ้าเข้าได้ = ✅ Ubuntu Server พร้อมใช้!

## 🔌 Phase 2: ตั้งค่าเริ่มต้น Ubuntu Server

### 2.1 อัพเดทระบบ

```bash
sudo apt update
sudo apt upgrade -y
```

ถาม password → ใส่ password ของคุณ
รอ 5-10 นาที

### 2.2 ตั้ง Static IP (สำคัญมาก!)

⚠️ **ทำไมต้อง Static IP:** Pi 4 ที่ site จะเชื่อมเข้ามาที่เครื่องนี้ → ต้องรู้ IP คงที่ ถ้า DHCP เปลี่ยน IP → ระบบล่ม

**Step 1: ดู interface ปัจจุบัน**

```bash
ip addr show
```

จะเห็นบรรทัดเช่น:
```
2: enp0s31f6: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500
    inet 192.168.1.50/24 brd 192.168.1.255 scope global dynamic
```

จดชื่อ interface (เช่น `enp0s31f6`) ไว้

**Step 2: หา Gateway**

```bash
ip route | grep default
```

เห็นเช่น `default via 192.168.1.1` → Gateway = `192.168.1.1`

**Step 3: แก้ Netplan config**

```bash
sudo nano /etc/netplan/50-cloud-init.yaml
```

แก้เป็น (เปลี่ยนชื่อ interface ตามของคุณ):

```yaml
network:
  version: 2
  ethernets:
    enp0s31f6:                    # ← เปลี่ยนเป็นชื่อ interface ของคุณ
      dhcp4: false
      addresses:
        - 192.168.1.50/24         # ← IP ที่อยากให้เป็น Static
      routes:
        - to: default
          via: 192.168.1.1        # ← Gateway
      nameservers:
        addresses:
          - 1.1.1.1
          - 8.8.8.8
```

⚠️ **สำคัญ:** ต้องเป็น YAML — เว้น vรรค (indent) ต้องเป็น **space ไม่ใช่ tab** และต้องตรงกัน!

**Step 4: Save**
- Ctrl+O → Enter (save)
- Ctrl+X (exit)

**Step 5: Apply**

```bash
sudo netplan apply
```

ถ้า error → แก้ไฟล์ใหม่ตาม error message

**Step 6: Verify**

```bash
ip addr show
ping -c 3 8.8.8.8
```

ต้อง:
- IP ต้องเป็น 192.168.1.50 (หรือที่ตั้ง)
- ping ออกได้

### 2.3 ทดสอบ SSH จากภายนอก

**จากคอม notebook ของคุณ (ในเครือข่ายเดียวกัน):**

```bash
ssh <username>@192.168.1.50
```

ถ้าใส่ password แล้วเข้าได้ = ✅

ถ้าเข้าไม่ได้:
- เช็ค firewall: `sudo ufw status` (ที่ Desktop)
- เช็ค SSH service: `sudo systemctl status ssh`

### 2.4 ตรวจสอบ Public IP

```bash
curl ifconfig.me
echo ""
```

จะเห็น IP เช่น `203.150.123.45`

**🚨 จดไว้!** เป็น "Public IP" ที่ Pi 4 + remote clients จะเชื่อมเข้ามา

### 2.5 ตั้งค่า Router True ให้ Forward Port

เข้า web interface ของ True router (มักเป็น `192.168.1.1`):

**Login:**
- Username: `admin`
- Password: `admin` หรือ `password` หรือดูใต้ router

**ไปที่:** Advanced → NAT → Port Forwarding (หรือ Virtual Server)

**เพิ่ม rules ทีละข้อ:**

| Service Name | External Port | Internal IP | Internal Port | Protocol |
|---|---|---|---|---|
| OMR-SSH | 65222 | 192.168.1.50 | 65222 | TCP |
| Glorytun | 65001 | 192.168.1.50 | 65001 | TCP+UDP |
| Shadowsocks | 65101 | 192.168.1.50 | 65101 | TCP+UDP |
| MLVPN | 65201-65208 | 192.168.1.50 | 65201-65208 | UDP |
| OpenVPN | 65301 | 192.168.1.50 | 65301 | TCP |
| WireGuard | 51820 | 192.168.1.50 | 51820 | UDP |

⚠️ **เปลี่ยน 192.168.1.50 เป็น Static IP ของ Desktop ที่ตั้งไว้**

Save → router อาจ reboot

### 2.6 ทดสอบ Port Forwarding

**จาก notebook ที่ต่อ 4G (ห้ามเชื่อม WiFi ออฟฟิศ!):**

```bash
nc -zv <public-ip> 22
```

หมายเหตุ: ตอนนี้ port 22 ยังเปิด เพราะยังไม่ได้รัน OMR script

ถ้าได้ "Connection succeeded" = port forwarding ทำงาน!

ถ้าไม่ได้:
- เช็ค port forwarding rules ใน router
- เช็คว่า ISP ของ True ไม่ได้ block port 22 (บางครั้ง block)

### 2.7 ตั้ง Hostname (เผื่ออยากใช้ DDNS)

```bash
sudo hostnamectl set-hostname omr-server
```

## 🚀 Phase 3: ติดตั้ง OpenMPTCProuter Server

### 3.1 ตรวจสอบความพร้อม

```bash
# ตรวจ kernel version (จะถูกแทนที่)
uname -r

# ตรวจ CPU
lscpu | head -10

# ตรวจ disk free
df -h /
```

ต้องมี:
- Disk เหลือ > 10GB
- RAM > 1GB (ของคุณเหลือเฟือ)

### 3.2 เปลี่ยนเป็น root

```bash
sudo su -
```

(พิมพ์ password ของคุณ)

ตอนนี้ prompt จะเป็น `root@omr-server:~#`

### 3.3 รัน OMR Install Script

```bash
wget -O - https://www.openmptcprouter.com/server/debian-x86_64.sh | KERNEL="6.12" sh
```

(ถ้า Ubuntu 24.04 → ใช้ KERNEL="6.12" ส่วน Ubuntu เก่ากว่าอาจใช้ค่าอื่น)

**Script จะถามคำถามต่างๆ — ตอบ Y กับทุกอัน**

ตัวอย่างคำถามที่จะเจอ:
```
Do you want to update the system? [Y/n] → Y
Do you want to install the new kernel? [Y/n] → Y
Do you want to install Shadowsocks? [Y/n] → Y
Do you want to install Glorytun? [Y/n] → Y
Do you want to install MLVPN? [Y/n] → Y
Do you want to install OpenVPN? [Y/n] → Y
Do you want to install IPerf3? [Y/n] → Y
Configure SSH on port 65222? [Y/n] → Y
```

### 3.4 รอ Script ทำงาน (สำคัญมาก!)

**ใช้เวลา 30-60 นาที** ขึ้นกับ:
- ความเร็ว Internet
- สเปคเครื่อง
- จำนวน package

**ห้ามปิด terminal! ห้ามตัดไฟ!**

ถ้ากลัว session ขาด — ใช้ `screen` หรือ `tmux`:

```bash
# ก่อนรัน script
apt install screen -y
screen -S omr-install

# ใน screen session
wget -O - https://www.openmptcprouter.com/server/debian-x86_64.sh | KERNEL="6.12" sh

# ถ้าหลุด session → re-attach
screen -r omr-install
```

### 3.5 จด Keys ที่ Script สร้างให้

**🚨🚨🚨 สำคัญที่สุดในขั้นตอนนี้!**

เมื่อ script ใกล้เสร็จ จะแสดงตาราง keys แบบนี้:

```
+----------------------------+---------------------------------------------+
| Service                    | Key                                         |
+----------------------------+---------------------------------------------+
| Shadowsocks key            | xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx           |
| Glorytun key               | yyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy           |
| Glorytun UDP key           | zzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzz           |
| MLVPN password             | aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa           |
| OpenVPN client.ovpn        | <large block of text>                       |
| MPTCP over VPN             | bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb           |
+----------------------------+---------------------------------------------+
```

**Copy ทั้งหมด** ไปเก็บไว้ในไฟล์ที่ปลอดภัย (เช่น password manager หรือ note encrypted)

**ถ้าไม่ทันจด:** สามารถดูภายหลังได้:

```bash
# ดู config OMR
cat /root/openmptcprouter_config

# ดู Shadowsocks key
cat /etc/shadowsocks-libev/manager.json

# ดู Glorytun key
cat /etc/glorytun-tcp/tun0.key
cat /etc/glorytun-udp/tun0.key
```

### 3.6 Reboot

```bash
reboot
```

⚠️ **หลัง reboot SSH port เปลี่ยนเป็น 65222!**

### 3.7 Login ใหม่ผ่าน Port 65222

จาก notebook ของคุณ:

```bash
# ที่ออฟฟิศ (ใน LAN)
ssh -p 65222 <username>@192.168.1.50

# หรือจากภายนอก (ใช้ Public IP)
ssh -p 65222 <username>@<public-ip>
```

ถ้าเข้าได้ = ✅ **OMR Server พร้อมใช้แล้ว!**

## 🔍 Phase 4: ตรวจสอบ OMR ทำงานจริง

### 4.1 ตรวจสอบ Services ทั้งหมดทำงาน

```bash
sudo systemctl status shadowsocks-libev-manager
sudo systemctl status glorytun-tcp@tun0
sudo systemctl status glorytun-udp@tun0
sudo systemctl status mlvpn@general
```

ทุกอันควร: `active (running)` = ✅

ถ้ามีตัวไหน `failed`:
```bash
journalctl -u <service-name> -n 50
```

ดู error message → ถ้าไม่เข้าใจส่งให้ผมดู

### 4.2 ตรวจสอบ Ports ที่เปิด

```bash
sudo ss -tulnp | grep -E '65|51820'
```

ควรเห็น:
```
tcp   LISTEN  0  128  *:65222   *:*  (sshd)
tcp   LISTEN  0  128  *:65001   *:*  (glorytun)
udp   UNCONN  0  0    *:65001   *:*  (glorytun)
tcp   LISTEN  0  128  *:65101   *:*  (shadowsocks)
udp   UNCONN  0  0    *:65101   *:*  (shadowsocks)
udp   UNCONN  0  0    *:65201   *:*  (mlvpn)
...
```

### 4.3 ตรวจสอบ Firewall

```bash
sudo iptables -L -n -v | head -30
```

OMR script จะตั้ง iptables rules อัตโนมัติ — ดูคร่าวๆ ว่ามี rules

### 4.4 ทดสอบจากภายนอก

จาก notebook ที่ต่อ 4G (ห้ามเชื่อม WiFi ออฟฟิศ!):

```bash
# Test SSH
nc -zv <public-ip> 65222

# Test Glorytun
nc -zv -u <public-ip> 65001

# Test WireGuard port (ยังไม่ได้ตั้ง แต่ port forward ไว้แล้ว)
nc -zv -u <public-ip> 51820
```

ถ้าทุกอันได้ "Connection succeeded" = ✅ **VPS พร้อม!**

## 🔐 Phase 6: ติดตั้ง WireGuard เพิ่ม (สำหรับ Remote Client)

OMR ไม่ติดตั้ง WireGuard ให้อัตโนมัติ — ต้องลงเอง

### 6.1 ติดตั้ง WireGuard

```bash
sudo apt install wireguard wireguard-tools -y
```

### 6.2 Generate Server Keys

```bash
cd /etc/wireguard
sudo umask 077

sudo wg genkey | sudo tee server-private.key | sudo wg pubkey | sudo tee server-public.key

# ดู keys
sudo cat server-private.key
sudo cat server-public.key
```

จด **server-public.key** ไว้

### 6.3 หา Interface ที่ต่อ Internet

```bash
ip route | grep default
```

จะเห็นเช่น `default via 192.168.1.1 dev enp0s31f6` → interface คือ `enp0s31f6`

### 6.4 สร้าง wg0.conf

```bash
sudo nano /etc/wireguard/wg0.conf
```

ใส่ (เปลี่ยน <ค่า> ให้ตรงกับของคุณ):

```ini
[Interface]
Address = 10.10.0.1/24
ListenPort = 51820
PrivateKey = <แทนที่ด้วย server-private.key>
SaveConfig = false

# NAT/Routing rules
PostUp   = iptables -A FORWARD -i %i -j ACCEPT; iptables -A FORWARD -o %i -j ACCEPT; iptables -t nat -A POSTROUTING -o enp0s31f6 -j MASQUERADE
PostDown = iptables -D FORWARD -i %i -j ACCEPT; iptables -D FORWARD -o %i -j ACCEPT; iptables -t nat -D POSTROUTING -o enp0s31f6 -j MASQUERADE

# === Client peers (เพิ่มข้างล่าง) ===
```

⚠️ เปลี่ยน `enp0s31f6` เป็น interface ของคุณ!

Save: Ctrl+O → Enter → Ctrl+X

### 6.5 เปิด IP Forwarding

```bash
echo "net.ipv4.ip_forward=1" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

ควรเห็น `net.ipv4.ip_forward = 1`

### 6.6 Start WireGuard

```bash
sudo systemctl enable wg-quick@wg0
sudo systemctl start wg-quick@wg0

# เช็ค status
sudo wg show
sudo systemctl status wg-quick@wg0
```

### 6.7 Generate Client Configs

ทำซ้ำสำหรับแต่ละ client (มือถือ, laptop, tablet, etc.)

```bash
sudo mkdir -p /etc/wireguard/clients
cd /etc/wireguard/clients

# Client 1
sudo wg genkey | sudo tee client1-private.key | sudo wg pubkey | sudo tee client1-public.key
```

### 6.8 เพิ่ม Peer ใน wg0.conf

```bash
sudo nano /etc/wireguard/wg0.conf
```

เพิ่มใต้สุดของไฟล์:

```ini
[Peer]
# Client 1 - phone
PublicKey = <client1-public.key>
AllowedIPs = 10.10.0.2/32

[Peer]
# Client 2 - laptop
PublicKey = <client2-public.key>
AllowedIPs = 10.10.0.3/32
```

### 6.9 Reload WireGuard

```bash
sudo systemctl restart wg-quick@wg0
sudo wg show
```

ควรเห็น peers ที่เพิ่มเข้าไป

### 6.10 สร้าง Client Config File

สำหรับ client 1:

```bash
sudo nano /etc/wireguard/clients/client1.conf
```

ใส่:

```ini
[Interface]
PrivateKey = <client1-private.key>
Address = 10.10.0.2/32
DNS = 1.1.1.1, 8.8.8.8

[Peer]
PublicKey = <server-public.key>
Endpoint = <public-ip>:51820
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25
```

### 6.11 ส่ง Config ให้ Client

**วิธีที่ 1: QR Code (สำหรับมือถือ)**

```bash
sudo apt install qrencode -y
sudo cat /etc/wireguard/clients/client1.conf | qrencode -t ansiutf8
```

จะเห็น QR code ใน terminal → สแกนด้วยแอพ WireGuard บนมือถือ

**วิธีที่ 2: ส่งไฟล์**

```bash
# Copy file ไปที่ home directory ก่อน
sudo cp /etc/wireguard/clients/client1.conf /home/<username>/
sudo chown <username>:<username> /home/<username>/client1.conf

# จาก notebook ที่ใช้
scp -P 65222 <username>@<public-ip>:~/client1.conf .
```

แล้วส่งไฟล์ผ่าน email/Drive ให้ user

### 6.12 ติดตั้ง Client บนมือถือ

**iOS/Android:**
1. ติดตั้งแอพ **WireGuard** (official) จาก App Store/Play Store

3. Toggle ON

## 🛡️ Phase 7: ตั้งค่าความปลอดภัยเพิ่มเติม

### 7.1 ปิด Password SSH (ใช้ Key เท่านั้น)

```bash

```
PasswordAuthentication no
PermitRootLogin no
PubkeyAuthentication yes
```

```

## 🎓 Phase 8: ตั้งค่า Dynamic DNS (ถ้า Public IP เปลี่ยน)

ถ้า Public IP ของออฟฟิศเปลี่ยน → Pi 4 หาเครื่องไม่เจอ
แก้ด้วย DDNS (Dynamic DNS) — แทนที่จะใช้ IP, ใช้ hostname เช่น `myomrserver.duckdns.org`

### 8.1 สมัคร DuckDNS (ฟรี)

1. ไปที่ **https://www.duckdns.org/**
2. Login ด้วย Google/GitHub
3. สร้าง domain เช่น `myomrserver.duckdns.org`
4. จด **token** ที่ได้

### 8.2 ติดตั้ง Update Script

```bash
mkdir -p ~/duckdns
cd ~/duckdns

# สร้าง script
cat > duck.sh << 'EOF'
echo url="https://www.duckdns.org/update?domains=YOUR_DOMAIN&token=YOUR_TOKEN&ip=" | curl -k -o ~/duckdns/duck.log -K -
EOF

# แก้ YOUR_DOMAIN และ YOUR_TOKEN
nano duck.sh

# ให้สิทธิ์
chmod 700 duck.sh

# Test
./duck.sh
cat duck.log  # ควรเห็น "OK"
```

### 8.3 ตั้ง Cron Job (ทุก 5 นาที)

```bash
crontab -e
```

เพิ่ม:
```
*/5 * * * * ~/duckdns/duck.sh >/dev/null 2>&1
```

Save → ตอนนี้ทุก 5 นาที DuckDNS จะถูก update IP

### 8.4 ใช้ Hostname แทน IP

ตอน config Pi 4 OMR Wizard:
- Server IP: เปลี่ยนจาก `203.150.xx.xx` → `myomrserver.duckdns.org`

## 🆘 Troubleshooting

### ❌ ติดตั้ง OMR script ไม่สำเร็จ

```bash
# ลบ kernel เก่าออก
sudo apt autoremove --purge linux-image-* -y
sudo apt update
sudo reboot

# ลองรัน script อีกครั้ง
```

### ❌ SSH เข้าไม่ได้หลัง reboot

**สาเหตุ:** Port เปลี่ยนเป็น 65222

```bash
# ใช้ port ใหม่
ssh -p 65222 <username>@<public-ip>
```

ถ้ายังไม่ได้ → SSH local จากออฟฟิศก่อน:
```bash
ssh -p 65222 <username>@192.168.1.50
```

### ❌ Service ไม่ start

```bash
# เช็ค status
sudo systemctl status <service-name>

# เช็ค log
sudo journalctl -xeu <service-name>

# ลอง restart
sudo systemctl restart <service-name>
```

### ❌ Pi 4 เชื่อม OMR server ไม่ได้

เช็คทีละขั้น:

1. **Public IP ถูกไหม?** จาก notebook ที่ต่อ 4G:
   ```bash
   ping <public-ip>
   nc -zv <public-ip> 65222
   ```

2. **Port forward ทำงานไหม?**
   - ใช้ https://www.yougetsignal.com/tools/open-ports/
   - ใส่ Public IP + port 65222 → ต้อง "open"

3. **Keys ตรงกันไหม?**
   - บน Desktop: `cat /root/openmptcprouter_config`
   - บน Pi: System → OpenMPTCProuter → Settings → ดู keys
   - ต้องตรงกัน
