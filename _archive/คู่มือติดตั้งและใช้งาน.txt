ระบบ v12 แยกออกเป็น 3 service ทำงานพร้อมกัน:

   │  Web UI  (React + Vite)                                         │

   └────────────────┬─────────────────────────────┬──────────────────┘
                    │                             │

             /system, /cameras...)          /history, /report...)
                    │                             │
   ┌────────────────▼──────────────┐  ┌───────────▼─────────────────┐
   │  Stream Server                │  │  Attendance API             │
   │  stream_server.py             │  │  api.py (FastAPI)           │
   │  port 8001                    │  │  port 8000                  │
   │                               │  │                             │
   │  - MJPEG live stream          │  │  - POST /attendance         │
   │  - JSON state (overlay)       │  │  - GET  /attendance/today   │
   │  - face crop snapshots        │  │  - GET  /history            │
   │  - Camera Config CRUD         │  │  - GET  /report/summary     │
   │  - Start/Stop ระบบ            │  │  - GET  /report/export      │
   │  - Camera Manager GUI /admin  │  │  - PUT/DELETE (Admin only)  │
   └────────────────┬──────────────┘  └───────────┬─────────────────┘
                    │                             │
                    └──────────┬──────────────────┘
                               │
                    ┌──────────▼──────────────────┐
                    │  Face Recognition Worker    │
                    │  main.py  (1 thread/cam)    │
                    │                             │
                    │  - InsightFace (ArcFace)    │
                    │  - Anti-Spoofing 7 ด่าน     │
                    │  - PicSAVE ลงดิสก์           │
                    │  - บันทึก IN/OUT ผ่าน api.py │
                    └─────────────────────────────┘

โหมดการทำงาน:
  • Direct mode    — รัน `python main.py` ตรง: main.py + stream_server.py
                     อยู่ใน process เดียวกัน (in-process buffer)
  • Headless mode  — Web UI กดปุ่ม Start: stream_server.py spawn main.py
                     เป็น subprocess แล้วสื่อสารผ่าน HTTP POST (in-memory)
                     เปิดด้วย FACE_HEADLESS=1

ฐานข้อมูล PostgreSQL ตาราง `attendance_logs`
  เก็บประวัติ IN/OUT ทั้งหมด — ข้อมูลพนักงาน (ชื่อ/ตำแหน่ง/หน่วยงาน) ดึงสด
  จาก External API ทุกครั้ง (ไม่มีตาราง employees อีกต่อไป — ดู migrate_v9.sql)

6. ตั้งค่า Secrets (.env)
================================================================================

ไฟล์ .env เก็บข้อมูลที่ละเอียดอ่อนทั้งหมด — ห้าม commit ขึ้น git เด็ดขาด

ขั้นตอนที่ 1 — คัดลอก template

    cp .env.example .env

ขั้นตอนที่ 2 — แก้ค่าจริงใน .env

    EXTERNAL_API_URL=https://your-api-url.example.com   ← URL ของ external API
    EXTERNAL_API_KEY=YOUR_API_KEY_HERE                  ← API Key ที่ได้รับมา
    ADMIN_API_KEY=YOUR_RANDOM_ADMIN_SECRET              ← key ของ PUT/DELETE endpoint

    # Ports — เปลี่ยนถ้ามี port ชน
    STREAM_PORT=8001
    API_PORT=8000
    LOCAL_API_URL=http://localhost:8000

    # Camera URL (ถ้ามีกล้องเดียวเป็น IP)
    CAMERA_URL=rtsp://admin:password@192.168.x.x:554/path

    # ตั้งชื่อ env var แยกตาม cam_id ก็ได้ (ดูหัวข้อ 9)
    # CAM1=rtsp://admin:password@192.168.1.13:554/Streaming/Channels/101
    # CAM2=rtsp://...

สร้าง ADMIN_API_KEY แบบสุ่ม:

    python -c "import secrets; print(secrets.token_hex(32))"

หมายเหตุ: ไม่ต้องแก้ URL หรือ key ใน config.py / api_client.py โดยตรง
          แก้ที่ .env ไฟล์เดียวพอ

7. ตั้งค่าฐานข้อมูล PostgreSQL
================================================================================

ขั้นตอนที่ 1 — สร้างฐานข้อมูล

    sudo -u postgres psql

    -- ใน psql:
    CREATE DATABASE faceattendance;
    CREATE USER facereg WITH PASSWORD 'รหัสผ่านของคุณ';
    GRANT ALL PRIVILEGES ON DATABASE faceattendance TO facereg;
    \q

ขั้นตอนที่ 2 — สร้างไฟล์ db_config.json (ในโฟลเดอร์โปรเจค — ห้าม commit)

    {
      "mode": "production",
      "production": {
        "host":     "localhost",
        "port":     5432,
        "database": "faceattendance",
        "user":     "facereg",
        "password": "รหัสผ่านของคุณ"
      }
    }

ขั้นตอนที่ 3 — สร้างตาราง attendance_logs

  ระบบใหม่ใช้ตารางเดียว (ลบตาราง employees แล้ว — ข้อมูลพนักงานดึงสดจาก
  External API ทุกครั้ง)

  สร้างตารางครั้งแรก:

      sudo -u postgres psql -d faceattendance <<'EOF'
      CREATE TABLE attendance_logs (
          id          SERIAL PRIMARY KEY,
          per_id      VARCHAR(13) NOT NULL,
          status      VARCHAR(8)  NOT NULL,
          camera_name VARCHAR(50),
          check_time  TIMESTAMP   NOT NULL,
          name        VARCHAR(200),
          prename_th  VARCHAR(100),
          per_name    VARCHAR(100),
          per_surname VARCHAR(100),
          posname_th  VARCHAR(200),
          organize_th VARCHAR(200),
          organize_id VARCHAR(20)
      );
      CREATE INDEX idx_attendance_per_id ON attendance_logs(per_id);
      CREATE INDEX idx_attendance_date   ON attendance_logs(DATE(check_time));
      EOF

  ถ้ามาจาก v8 หรือเก่ากว่า — ใช้ migration:

      sudo -u postgres psql -d faceattendance -f migrate_v9.sql

  (เปลี่ยน full_name → name, เพิ่ม columns ที่ขาด, rename employees → backup)

ขั้นตอนที่ 4 — (ตัวเลือก) ใส่ข้อมูลจำลอง

      sudo -u postgres psql -d faceattendance -f mock_attendance.sql

8. เพิ่มบุคคลเข้าระบบ + สร้าง Encodings
================================================================================

โครงสร้าง known_faces/

  - 1 โฟลเดอร์ = 1 คน
  - ชื่อโฟลเดอร์ต้องเป็น per_id (เลข 13 หลัก) เท่านั้น
  - ใส่ 3-5 รูปต่อคน หลายมุม หลายแสง

      known_faces/
      ├── 6666666666666/
      │   ├── front.jpg
      │   ├── left.jpg
      │   └── right.jpg
      └── 7777777777777/
          └── photo.jpg

[Mock Mode] เพิ่มข้อมูลใน api_client.py
  ถ้าจะใช้ MOCK_MODE = True ในไฟล์ api_client.py ต้องเพิ่มบุคคลใน
  _MOCK_PERSONS dict ให้ key (per_id) ตรงกับชื่อโฟลเดอร์ใน known_faces/:

      "1234567890123": {
          "per_id":         "1234567890123",
          "name":           "นาย สมชาย ใจดี",
          "prename_th":     "นาย",
          "per_name":       "สมชาย",
          "per_surname":    "ใจดี",
          "posname_th":     "เจ้าหน้าที่",
          "prenameth_abbr": "นาย",
          "organize_th":    "ฝ่ายวิจัย",
          "organize_id":    "0000001",
          "org_path_name":  "/หน่วยงาน/",
          "birthDate":      "1990-01-01",
          "per_picpath":    "",
      },

[Real API Mode] ระบบดึงข้อมูลตาม per_id อัตโนมัติ — ไม่ต้องแก้ไฟล์นี้

สร้าง Face Encodings (จำเป็นทุกครั้งที่เพิ่มคนใหม่):

    source venv/bin/activate

    # ปกติ — อ่านจาก known_faces/
    python encode_faces_arcface.py

    # โฟลเดอร์ชื่ออื่น
    python encode_faces_arcface.py --dir other_faces

    # โหลดรูปจาก URL
    python encode_faces_arcface.py --urls urls.json

รูปแบบ urls.json:

    [
      {
        "face_label": "6666666666666",
        "urls": [
          "https://example.com/person1_a.jpg",
          "https://example.com/person1_b.jpg"
        ]
      }
    ]

หมายเหตุ:
  - ครั้งแรกที่รันจะดาวน์โหลดโมเดล buffalo_l (~300 MB) อัตโนมัติ
  - ผลลัพธ์: encodings.pkl ในโฟลเดอร์โปรเจค

9. ตั้งค่ากล้อง (Single + Multi-Camera)
================================================================================

ระบบ v12 รองรับหลายกล้องพร้อมกัน — แต่ละกล้องมี ID, name, URL/index, flip
ของตัวเอง บริหารจัดการได้ผ่าน Web UI โดยตรง

---- วิธีที่ 1 (แนะนำ): จัดการผ่าน Web UI ----

  1. รันระบบ (ดูหัวข้อ 11)
  2. เปิด http://localhost:5173 (dev) หรือ http://localhost:8001/admin
  3. กด "+ เพิ่มกล้อง" → กรอก ชื่อ, ประเภท (USB/IP), index/URL, flip
  4. ระบบจะบันทึก cameras.json ให้อัตโนมัติ
  5. กด Reload (R) เพื่อ hotload โดยไม่ต้อง restart

---- วิธีที่ 2: แก้ cameras.json ตรงๆ ----

  รูปแบบไฟล์:

      [
        {
          "id":    "cam1",
          "name":  "CAM_MAIN",
          "url":   "$CAM1",        ← อ่านค่าจาก env var (ดูด้านล่าง)
          "flip":  false
        },
        {
          "id":    "cam2",
          "name":  "CAM_WEB",
          "index": 1,              ← USB index
          "flip":  true
        }
      ]

  Field:
    id     — unique ใช้เป็น key สำหรับ /stream/{id}, /state/{id}
    name   — ชื่อกล้องที่บันทึกใน attendance_logs.camera_name
    url    — RTSP/HTTP URL (IP camera) — ขึ้นต้น "$" = ชื่อ env var
    index  — USB index (0, 1, 2 ...) — ใส่อันใดอันหนึ่งระหว่าง url กับ index
    flip   — กลับซ้าย-ขวา

  [ความปลอดภัย] วาง credentials ไว้ใน .env ห้ามใส่ใน cameras.json:

      .env:
        CAM1=rtsp://admin:secret@192.168.1.13:554/Streaming/Channels/101
        CAM2=rtsp://admin:secret@192.168.1.14:554/cam/realmonitor

      cameras.json:
        { "id": "cam1", "name": "CAM_MAIN", "url": "$CAM1", "flip": false }

---- รูปแบบ RTSP ตามยี่ห้อกล้อง ----

  Hikvision:  rtsp://admin:pass@192.168.1.13:554/Streaming/Channels/101
  Dahua:      rtsp://admin:pass@192.168.1.13:554/cam/realmonitor?channel=1&subtype=0
  UNV/Generic: rtsp://admin:pass@192.168.1.13:554/unicast/c1/s0/live

ทดสอบ URL ด้วย VLC: Media → Open Network Stream → วาง RTSP URL

---- USB Camera ----

  ใส่ index (0=built-in, 1=USB ตัวแรก, ...) — ตรวจ index ด้วย:

      python -c "import cv2; cap=cv2.VideoCapture(0); print('OK' if cap.isOpened() else 'FAIL')"

10. ตั้งค่า External API (Mock / Real)
================================================================================

---- Mock Mode (ทดสอบโดยไม่ต้องมี external API) ----

  แก้ใน api_client.py:
    MOCK_MODE = True

  ระบบจะดึงข้อมูลจาก _MOCK_PERSONS dict (ดูหัวข้อ 8)
  เหมาะสำหรับ dev / demo

---- Real API Mode (Production) ----

  แก้ใน api_client.py:
    MOCK_MODE = False

  ตั้ง URL + Key ใน .env:
    EXTERNAL_API_URL=https://service-ps.example.com
    EXTERNAL_API_KEY=YOUR_API_KEY_HERE

  ระบบจะเรียก:
    POST {EXTERNAL_API_URL}/api/check-emp
    Header: x-api-key: {EXTERNAL_API_KEY}
    Body:   { "per_cardno": "<per_id>" }

  Response ต้องมี: per_name, per_surname, prenameth_abbr,
                   prename_th, posname_th, organize_th, organize_id

---- Admin Key (PUT/DELETE attendance_logs) ----

  endpoint แก้ไข/ลบ record ต้องการ header:
    X-Admin-Key: <ค่า ADMIN_API_KEY ใน .env>

  ตัวอย่าง:
    curl -X DELETE http://localhost:8000/attendance/5 \
         -H "X-Admin-Key: YOUR_ADMIN_KEY"

11. รันระบบ
================================================================================

มี 3 service ที่ต้องรัน — เลือกวิธีใดวิธีหนึ่ง

---- วิธีที่ 1 (แนะนำ): one-shot ผ่าน npm run dev ----

  เปิด stream + api + Web UI พร้อมกันใน terminal เดียว:

      cd front_end
      npm run dev

  จะเห็น log สี 3 ชุด:
    cyan    [stream] = stream_server.py (port 8001)
    magenta [api]    = uvicorn api:app  (port 8000)
    green   [vite]   = Web UI dev       (port 5173)

  เปิด browser: http://localhost:5173
  → กดปุ่ม Start ในหน้า LiveCam → main.py จะ spawn อัตโนมัติ (headless mode)

---- วิธีที่ 2: รัน main.py ตรงๆ (มีหน้าต่าง OpenCV) ----

  Terminal 1 — Attendance API:
      source venv/bin/activate
      uvicorn api:app --host 0.0.0.0 --port 8000

  Terminal 2 — Main loop (รวม stream_server ภายใน):
      source venv/bin/activate
      python main.py
      # หรือใช้ profile:
      python main.py cam_main
      python main.py cam_usb
      python main.py test

  Terminal 3 (ตัวเลือก) — Web UI:
      cd front_end
      npm run dev

---- วิธีที่ 3: standalone stream server ----

  ใช้กรณีรัน stream server แยก (ไม่ start main.py ทันที):
      python stream_server.py

  แล้วเปิด http://localhost:8001/admin → กด Start

สิ่งที่ต้องมีก่อนรัน:
  ✓ ไฟล์ .env             (หัวข้อ 6)
  ✓ ไฟล์ db_config.json   (หัวข้อ 7)
  ✓ ไฟล์ encodings.pkl    (หัวข้อ 8)
  ✓ ไฟล์ cameras.json     (หัวข้อ 9 — สร้างได้จาก Web UI)
  ✓ ฟอนต์ภาษาไทย          (หัวข้อ 3)

13. Profiles (สลับโหมดเร็ว)
================================================================================

Profile = ไฟล์ Python ใน profiles/ ที่ override ค่าจาก config.py

ตัวอย่าง profiles/cam_usb.py:

    CAMERA_URL   = None
    CAMERA_FLIP  = True
    FULLSCREEN   = True
    TEST_MODE    = False

วิธีใช้:

    python main.py cam_usb                      ← argument
    FACE_PROFILE=cam_usb python main.py         ← env var

profile ที่มากับระบบ:
  cam_main  — IP Camera หลัก (อ่าน CAMERA_URL จาก .env)
  cam_usb   — USB / Webcam (CAMERA_URL=None, CAMERA_FLIP=True)
  test      — โหมดทดสอบ 60 วิ ไม่ fullscreen

สร้าง profile ใหม่: สร้างไฟล์ profiles/<name>.py ใส่เฉพาะค่าที่ต้องการ override

14. Active Windows (ตารางเวลา)
================================================================================

ระบบรัน 24/7 แต่ตรวจใบหน้าเฉพาะในช่วง ACTIVE_WINDOWS เท่านั้น
นอกช่วง → Idle mode: หยุดประมวลผล ประหยัด CPU/GPU

แก้ใน config.py:

    from datetime import time as dtime

    ACTIVE_WINDOWS = [
        (dtime(5, 0), dtime(22, 0)),   # 05:00 - 22:00
    ]

  รองรับช่วงข้ามเที่ยงคืน เช่น (dtime(23, 0), dtime(1, 0))
  ใส่ได้หลายช่วง: [ (dtime(7,0), dtime(9,0)), (dtime(16,0), dtime(18,0)) ]

15. PicSAVE — บันทึกรูปถาวร
================================================================================

ทุกครั้งที่ลง IN/OUT ระบบจะบันทึกรูปใบหน้าลงดิสก์อัตโนมัติ:

    PicSAVE/YYYY/MM/DD/HH-MM-SS_<per_id>_<IN|OUT>.jpg

  ตัวอย่าง:
    PicSAVE/2026/04/29/08-15-22_6666666666666_IN.jpg
    PicSAVE/2026/04/29/17-30-44_6666666666666_OUT.jpg

  - บันทึกโดย session.save_snapshots() ตอนจบ run_camera() loop
  - ใน headless mode: main.py จะ join camera threads ก่อน exit เพื่อให้ save ทัน
  - เก็บ per_id เต็ม (ไม่ mask) — ใช้ตามรอย และ audit ได้

ขนาดประมาณ 50-150 KB/รูป — ตรวจ disk usage เป็นระยะ

================================================================================
16. Anti-Spoofing Pipeline
================================================================================

ตรวจจับการปลอมแปลง 7 ด่านตามลำดับ — ตั้งค่าเปิด/ปิดได้ใน config.py

  ด่านที่  ชื่อด่าน          ตัวแปรปิด/เปิด           คำอธิบาย
  ──────  ────────────────   ─────────────────────    ────────────────────────────
  1       Landmark Depth     (เปิดตลอด)               ตรวจความลึก 3D 68-point
  2       Micro-Motion       (เปิดตลอด)               ต้องมีการขยับเล็กน้อย
  3       Blink Detection    BLINK_ENABLED            EAR — กะพริบ ≥ N ครั้ง
  4       Texture Analysis   TEXTURE_ENABLED          LBP + Laplacian + Chroma
  5       Screen Border      SCREEN_DETECT_ENABLED    Edge ratio + inner density
                             FFT_ENABLED              FFT score (ใช้คู่กับ Canny)
  6       Finger Challenge   CHALLENGE_ENABLED        ชูนิ้วตามที่ระบบสั่ง 2 ชุด
  7       MiniFASNet (AI)    FAS_ENABLED              AI ตรวจ spoof confidence

ปิดด่านที่ false positive บ่อย:

    SCREEN_DETECT_ENABLED = False   ถ้าใช้กล้อง wide-angle / fisheye
    BLINK_ENABLED         = False   ถ้าสภาพแสงในห้องมืดหรือไม่สม่ำเสมอ
    FFT_ENABLED           = False   ถ้ากล้องคุณภาพต่ำ noise สูง

ปรับ threshold ให้เข้มขึ้นเมื่อ false negative มาก:

    FAS_THRESHOLD         = 0.90    (default 0.90 — เพิ่มเป็น 0.95 ให้เข้มขึ้น)
    BLINK_MIN             = 2       (เพิ่มเป็น 3 ถ้าต้องการเข้มขึ้น)
    CHALLENGE_COUNT       = 2       (เพิ่มเป็น 3 ถ้าต้องการเข้มขึ้น)
