■ งานที่ดำเนินการในวันนี้
────────────────────────────────────────────────────────────────────────

1. เพิ่มการแสดงรูปภาพจาก External API บน Web Dashboard
   ─────────────────────────────────────────────────────────────────
   เดิม Web Dashboard ไม่มีการแสดงรูปโปรไฟล์พนักงาน
   เพิ่ม 2 endpoint ใหม่ใน api.py เพื่อแยกแหล่งรูปให้ชัดเจน:

   - เพิ่ม GET /person-profile/{per_id} — รูปโปรไฟล์จาก External API
       • ดึง per_picpath จาก External API ผ่าน fetch_person_by_pid()
       • Proxy รูปภาพกลับมาโดยตรง ไม่ redirect
       • Cache 1 ชั่วโมง (max-age=3600)
       • ถ้าไม่มีรูป → 404 (ไม่มี fallback)

   - แก้ไข GET /person-photo/{per_id}?status=IN|OUT — รูปจาก PicSAVE
       • ค้นหาไฟล์ *_{per_id}_IN.jpg / *_{per_id}_OUT.jpg ใน PicSAVE
       • ถ้าไม่มีไฟล์ → 404 (ไม่ fallback ไป External API)
       • ใช้สำหรับรูป verify ที่ถ่ายจากกล้องตอนเช็คชื่อเข้า/ออก

2. แก้ปัญหารูปไม่แสดงใน Production (VITE_API_BASE_URL prefix bug)
   ─────────────────────────────────────────────────────────────────
   พบว่า AttendanceFeed.vue และ LiveDetection.vue ใช้ URL hardcode
   เป็น /api/person-photo/ แต่ FastAPI ไม่มี route ที่ขึ้นต้นด้วย /api/
   (Vite dev proxy ตัด /api prefix ออกก่อนส่งต่อ แต่ production ไม่มี proxy)

   แก้ไข: เพิ่ม const API_BASE = import.meta.env.VITE_API_BASE_URL ?? '/api'
   ในทุก component ที่เรียก API แล้วใช้ ${API_BASE}/person-photo/ แทน

3. เพิ่มการแสดงรูปโปรไฟล์ใน LiveDetection ("ตรวจพบในกล้อง")
   ─────────────────────────────────────────────────────────────────
   เดิม LiveDetection.vue ใช้ /api/person-face/{per_id} ซึ่งไม่มี endpoint
   เปลี่ยนให้ใช้ /person-profile/{per_id} (External API เท่านั้น)
   ถ้าไม่มีรูปใน API → แสดงตัวอักษรย่อชื่อ (initial letter) แทน
   ถ้ามีรูปใน API → แสดงในวงกลมขนาด 36px พร้อม border

   - นำ faceTick ref และ setInterval timer ออก (ไม่จำเป็นแล้ว)
   - เพิ่ม faceErrors = reactive({}) สำหรับ track รูปที่โหลดไม่สำเร็จ

4. เพิ่มการแสดงรูปภาพใน AttendanceFeed ("รายชื่อเช็คชื่อเข้าออก")
   ─────────────────────────────────────────────────────────────────
   เดิม AttendanceFeed.vue ไม่มีรูปภาพเลย
   เพิ่ม avatar วงกลมขนาด 28px แสดงรูป verify จาก PicSAVE
   (/person-photo/{per_id}?status=IN หรือ OUT ตาม record นั้น)
   คลิกรูปเปิด lightbox แสดงรูปเต็มพร้อมชื่อ สถานะ และเวลา
   ถ้าโหลดรูปไม่ได้ → แสดงตัวอักษรย่อชื่อสีตาม status (เขียว IN / เหลือง OUT)

   - เปลี่ยน error tracking key จาก per_id เป็น log_id
     เพื่อให้ IN และ OUT ของคนเดียวกันมี error state แยกจากกัน
   - เพิ่ม lightboxRow ref + Teleport lightbox modal

5. เพิ่ม lightbox (click-to-fullscreen) บน PersonCard
   ─────────────────────────────────────────────────────────────────
   เดิม PersonCard.vue แสดงรูปแต่คลิกไม่ได้
   เพิ่ม lightboxOpen ref และ Teleport modal เพื่อแสดงรูปเต็มจอ
   ปิดได้ด้วยการกด Esc หรือคลิกนอกรูป

6. แยกแหล่งรูปของ PersonCard ด้วย prop photoMode
   ─────────────────────────────────────────────────────────────────
   เพิ่ม prop photoMode: 'profile' | 'verify' ใน PersonCard.vue
   - 'profile' (default): ดึงรูปจาก /person-profile/{per_id} (External API)
     ใช้ใน DashboardView "รายชื่อที่พบวันนี้"
   - 'verify': ดึงรูปจาก /person-photo/{per_id}?status=IN|OUT (PicSAVE)
     ใช้ใน CameraView "รายชื่อเช็คชื่อเข้าออก"

   CameraView.vue: เพิ่ม photo-mode="verify" บน PersonCard
   ใน loop checkedPersons เพื่อแสดงรูปที่ถ่ายตอนเช็คชื่อจริง

7. แก้การเรียงลำดับ "รายชื่อที่พบวันนี้" ให้เป็น FIFO
   ─────────────────────────────────────────────────────────────────
   เดิม DashboardView.vue จัดกลุ่ม IN ก่อน OUT แล้วเรียงภายในกลุ่ม
   เปลี่ยนให้เรียงตาม in_time จากน้อยไปมาก (คนที่มาก่อนแสดงก่อน)
   คนที่ยังไม่มี in_time (PENDING) แสดงท้ายสุด (ใช้ Infinity แทน)

■ ปัญหาที่พบและแนวทางแก้ไข
────────────────────────────────────────────────────────────────────────

  ปัญหา : รูปไม่แสดงใน production แต่ขึ้นในระหว่าง dev
  วิเคราะห์: Dev mode มี Vite proxy ตัด /api prefix ก่อนส่งต่อ FastAPI
             Production ไม่มี proxy → URL /api/person-photo/ ไม่มี route
             VITE_API_BASE_URL='' (empty string) ทำให้ควรใช้ /person-photo/
             แต่ component hardcode /api/ ไว้จึงเรียกผิด endpoint
  แก้ไข : เพิ่ม const API_BASE = import.meta.env.VITE_API_BASE_URL ?? '/api'
           ทุก component ที่เรียก API แล้วใช้ template literal แทน hardcode

  ปัญหา : AttendanceFeed รูป IN/OUT ของคนเดียวกันใช้ error state เดียวกัน
  วิเคราะห์: error tracking key ใช้ per_id ทำให้ error ของ IN record
             ทับ error ของ OUT record ของคนเดียวกัน
             ถ้า IN load ไม่ได้ OUT จะถูก fallback เป็น initial ด้วย
  แก้ไข : เปลี่ยน key เป็น log_id (unique ต่อ record ไม่ใช่ต่อคน)

  ปัญหา : รูปใน PersonCard ตัดเฉพาะส่วนลำตัว ไม่เห็นใบหน้า
  วิเคราะห์: CSS object-center ทำให้ center crop ตามค่า default
             รูปโปรไฟล์ส่วนใหญ่ใบหน้าอยู่ส่วนบนของภาพ
  แก้ไข : เปลี่ยนเป็น object-cover object-top ให้ crop จากด้านบน

1. เพิ่มหน้า Downloading บน Web Dashboard ขณะ main.py กำลังโหลด
   ─────────────────────────────────────────────────────────────────
   เดิมเมื่อผู้ใช้กดปุ่ม "▶ เปิด" บน Dashboard กล้องจะยังคงดำ
   ไม่มี feedback ใดๆ จนกว่า main.py จะโหลดเสร็จและส่ง frame มา
   (ซึ่งใช้เวลา 20–60 วินาที)
   เพิ่มหน้าโหลดพร้อม progress bar และข้อความบอก step ปัจจุบัน

   การทำงาน:
     main.py เขียนไฟล์ boot_status_{cam_id}.json ก่อนแต่ละขั้นตอน
     api.py อ่านไฟล์นั้นและส่ง boot_msg กลับใน /cameras/{id}/face/status
     Dashboard poll status ทุก 2 วินาที และแสดงข้อความตาม boot_msg

   - เพิ่ม _BOOT_PATH, _write_boot(msg), _clear_boot() ใน main.py
       • _write_boot() เรียกก่อนแต่ละขั้นตอนใหญ่ในช่วง startup
         — "กำลังโหลดฐานข้อมูลใบหน้า..."
         — "กำลังโหลด AI Model (InsightFace)..."
         — "กำลังเปิดกล้อง..."
         — "กำลังติดตั้งระบบตรวจจับ..."
       • _clear_boot() เรียกทันทีที่เข้า main loop (โหลดเสร็จแล้ว)
       • path รับจาก env var FACE_BOOT_PATH เพื่อแยกไฟล์ตาม cam_id

   - เพิ่ม _boot_path_for(cam_id) และ boot_msg ใน api.py
       • cameras_face_start() ส่ง FACE_BOOT_PATH เป็น env var ให้ main.py
       • cameras_face_status() อ่านไฟล์ boot_status_{cam_id}.json
         แล้วคืน boot_msg ใน JSON response

   - เพิ่ม isBooting / bootMsg state ใน CameraView.vue
       • startFace() ตั้ง isBooting=true ทันทีที่กดปุ่ม
       • fetchStatus() ล้าง isBooting เมื่อ has_frame=true หรือ running=false
       • หน้า Downloading แสดงเมื่อ isBooting=true แทน frame ดำ

   - เพิ่ม isBooting / bootMsg state ใน SingleCameraView.vue
       • camStarting computed รวม isStarting || isBooting
       • แสดง Downloading screen เช่นเดียวกับ CameraView

2. ปรับ Progress Bar ให้สอดคล้องกับขั้นตอนโหลดจริง
   ─────────────────────────────────────────────────────────────────
   เดิม progress bar ใช้ CSS animation ปลอม (0% → 93% ใน 60 วินาที)
   ซึ่งไม่สัมพันธ์กับการโหลดจริงของ main.py เลย
   เปลี่ยนให้ bar กระโดดไปตำแหน่งจริงเมื่อ boot_msg เปลี่ยนแต่ละ step

   Mapping bootMsg → ความคืบหน้า:
     เริ่มต้น (ยังไม่มี msg)               →  5%
     กำลังโหลดฐานข้อมูลใบหน้า             → 20%
     กำลังโหลด AI Model (InsightFace)      → 50%
     กำลังเปิดกล้อง                        → 75%
     กำลังติดตั้งระบบตรวจจับ               → 90%
     โหลดเสร็จ (isBooting=false)           → 100%

   - แก้ไข CameraView.vue
       • เพิ่ม _BOOT_STEPS map และ bootProgressFor(camId) function
       • bar ใช้ :style="width:${bootProgressFor(cam.id)}%;
         transition:width 0.8s ease" แทน CSS animation class
       • ลบ @keyframes dl-fill-cam และ .dl-bar-cam ออก

   - แก้ไข SingleCameraView.vue
       • เพิ่ม _BOOT_STEPS map และ camBootProgress computed
       • bar ใช้ :style="width:${camBootProgress}%;
         transition:width 0.8s ease" แทน CSS animation class
       • ลบ @keyframes dl-fill-single และ .dl-bar-single ออก

       • ล้มเหลว → alert แสดงเหตุผล

2. เพิ่มโหมด CCTV บน Web Dashboard
   ─────────────────────────────────────────────────────────────────
   เดิม Web Dashboard แสดงหน้ากล้องเพียงอย่างเดียว ไม่มีโหมด CCTV
   เพิ่มระบบตรวจสอบเวลาและ route พิเศษเพื่อรองรับโหมด CCTV

   - เพิ่ม GET /system/mode ใน api.py
       • อ่าน ACTIVE_WINDOWS จาก config.py

3. แก้ไขให้ Web Dashboard ทำงานตาม GUI (main.py) อย่างถูกต้อง
   ─────────────────────────────────────────────────────────────────
   พบว่า Web Dashboard ที่ implement ไว้ไม่ทำงานตามที่ออกแบบไว้
   เนื่องจาก main.py ที่ spawn จาก api.py ไม่เข้า CCTV mode เลย

   สาเหตุ — Priority bug ใน main.py
     api.py spawn main.py พร้อม env vars FACE_CAMERA_CHILD=1 และ
     FACE_ALWAYS_ACTIVE=1 ทั้งคู่ แต่ใน main.py ตรวจ _DASHBOARD_CHILD

     ไม่ถูกตรวจเลย → main.py ไม่เคยเข้า CCTV mode
     แก้ไข: สลับลำดับ if ให้ตรวจ _ALWAYS_ACTIVE ก่อน _DASHBOARD_CHILD
             _DASHBOARD_CHILD มีไว้ป้องกัน recursive spawn เท่านั้น
             ยังสามารถ respect ACTIVE_WINDOWS ได้

   สาเหตุ — main.py ไม่เขียน live_state ในโหมด CCTV

     แก้ไข: เพิ่มการเขียน live_state (active=False) ใน CCTV block

   สาเหตุ — session_live() แยกไม่ออกระหว่าง CCTV กับ offline

     แก้ไข: ตั้ง any_active=True เฉพาะเมื่อ ts recent AND data.active=True

   - เพิ่ม POST /attendance/auto-checkout ใน api.py
       • ค้นหาทุกคนที่มี IN แต่ไม่มี OUT วันนี้ ด้วย DISTINCT ON (per_id)
       • แทรก OUT record ทั้งหมดพร้อมกัน

   - เพิ่ม background scheduler _mode_watcher_task() ใน api.py
       • รันเป็น asyncio coroutine ตั้งแต่ startup
       • ตรวจ /system/mode ทุก 30 วินาที
       • เมื่อตรวจพบ mode เปลี่ยนจาก face → cctv เรียก auto-checkout อัตโนมัติ

■ งานที่ดำเนินการในวันนี้
────────────────────────────────────────────────────────────────────────

1. แก้ปัญหา Frame Lag / Stuttering บน Docker Web Dashboard
   ─────────────────────────────────────────────────────────────────
   วิเคราะห์และแก้ไขสาเหตุที่ทำให้ MJPEG stream บน Web Dashboard
   มีการกระตุกและหน่วงเวลาสูงเมื่อ Deploy บน Docker (CPU-only)

   สาเหตุที่ 1 — api.py ส่ง frame ซ้ำ
     generate() ใน /camera/face-stream และ /cameras/{id}/face-stream
     ใช้ time.sleep(0.067) ส่ง live_frame.jpg ทุก 67ms โดยไม่ตรวจว่า
     ไฟล์เปลี่ยนหรือยัง ทำให้ browser ได้รับ frame เดิมซ้ำๆ 10-15 ครั้ง
     ระหว่างที่ main.py กำลัง process อยู่ → เห็นเป็น "แช่ → กระโดด"
     แก้ไข: เพิ่ม mtime tracking ด้วย stat().st_mtime ส่งเฉพาะเมื่อ
             ไฟล์เปลี่ยนจริง เพิ่ม poll rate จาก 15fps → 30fps

   สาเหตุที่ 2 — Disk I/O jitter จาก Docker overlay filesystem
     live_frame.jpg เขียน/อ่านผ่าน Docker overlay filesystem
     มี latency ไม่สม่ำเสมอทำให้ stream กระตุกไม่สม่ำเสมอ
     แก้ไข: เพิ่ม tmpfs mount ที่ /tmp/frames (RAM disk 32MB)
             เพิ่ม FACE_FRAMES_DIR env var ใน api.py และ docker-compose
             ให้ frame files ทั้งหมดเขียน/อ่านจาก RAM แทน disk

   สาเหตุที่ 3 — InsightFace บน CPU ช้า
     ไม่มี GPU → InsightFace detection ใช้เวลา 50-200ms ต่อเฟรม
     ทำให้ main.py loop ช้าลงเหลือ 1-5fps แทนที่จะเป็น 15fps
     แก้ไข: เพิ่ม FACE_DET_SIZE=160 (ลดจาก 320 → เร็วขึ้น ~4x)
             เพิ่ม FACE_DETECT_EVERY_N=5 (detect ทุก 5 frames)
             เพิ่ม FACE_STREAM_JPEG_QUALITY=50 (ลด I/O ~30%)

   สาเหตุที่ 4 — MiniFASNet (TensorFlow) spike
     MiniFASNet รัน TensorFlow บน CPU ใช้ 200-800ms ต่อครั้ง
     ทำให้เกิด spike กระตุกเป็นช่วงๆ ทุก 2-3 วินาที
     แก้ไข: เพิ่ม FAS_ENABLED env var ใน config.py
             ตั้ง FAS_ENABLED=false ใน docker-compose เพื่อปิดบน Docker

2. แก้ปัญหา Timezone ไม่ตรง
   ─────────────────────────────────────────────────────────────────
   Docker container รันด้วย UTC (เวลาสากล) ทำให้เวลาบันทึก
   การลงเวลาต่างจากเวลาจริงในไทย 7 ชั่วโมง
   แก้ไข: เพิ่ม TZ: Asia/Bangkok ใน docker-compose.yml environment

3. เปิดให้เข้าใช้งาน Web Dashboard จากเครื่องอื่นในวง LAN
   ─────────────────────────────────────────────────────────────────
   แก้ไข docker-compose.yml เปลี่ยน port mapping จาก 8000:8000
   เป็น 80:8000 ให้เข้าถึงได้ที่ http://<IP> โดยไม่ต้องใส่หมายเลข port
   ตรวจสอบ firewall (ufw inactive จึงไม่ต้องเปิด port เพิ่ม)
   URL สำหรับเครื่องอื่น: http://192.168.1.104/dashboard/

4. แก้ไขสีปุ่ม Start/Stop กล้องสำหรับ Light Theme
   ─────────────────────────────────────────────────────────────────
   ปุ่มรัน main.py ใช้สี gui-in (#00dc00 สีเขียวสด) แบบ hardcode
   ซึ่งมี contrast ต่ำมากบน light background (อัตราส่วน ~1.4:1)
   ทำให้ตัวอักษรกลมกลืนกับพื้นหลังอ่านไม่ออก

   แก้ไข style.css:
     - เพิ่ม CSS variables --gui-in, --gui-fail, --gui-out, --gui-warn
       แยก light/dark mode
     - Light: ใช้สีเข้ม (#16a34a เขียว, #dc2626 แดง) contrast ≥4.5:1
     - Dark: ใช้สีสดเดิม (#00dc00, #ff3333) ที่อ่านได้ดีบน background มืด
     - เพิ่ม .btn-cam-start และ .btn-cam-stop utility classes
       Light mode: solid background + white text (ชัดเจนสุด)
       Dark mode: semi-transparent + colored text (ดูเข้ากับ theme)

   แก้ไข tailwind.config.js:
     - เปลี่ยน gui-in, gui-fail, gui-out, gui-warn จาก hardcode สี
       เป็น rgb(var(--gui-*) / <alpha-value>) เพื่อรับค่าจาก CSS variable

   แก้ไข CameraView.vue:
     - เปลี่ยนปุ่ม 3 จุด (overlay เปิด, per-camera toggle, เปิด/หยุดทั้งหมด)
       ให้ใช้ class .btn-cam-start / .btn-cam-stop แทน inline Tailwind classes

5. Push Docker Image ขึ้น Docker Hub
   ─────────────────────────────────────────────────────────────────
   Build และ publish Docker image เพื่อให้เครื่องอื่นสามารถ
   pull มาใช้งานได้โดยไม่ต้อง build เอง

   - docker tag docker-api photcharap/face-attendance:latest
   - docker push photcharap/face-attendance:latest
   - Image พร้อมใช้งานที่ docker.io/photcharap/face-attendance

   ศึกษาและเตรียมขั้นตอน Deploy บนเครื่อง Windows:
   - ติดตั้ง Docker Desktop + WSL2
   - แก้ docker-compose.yml ให้ใช้ image จาก Hub แทน build
   - เปลี่ยน volume path เป็น Windows style (C:/Users/...)
   - comment devices (USB camera ไม่รองรับบน Windows)
   - รองรับ IP Camera (RTSP) ได้ปกติ
