■ งานที่ดำเนินการในวันนี้
────────────────────────────────────────────────────────────────────────

1. เพิ่มระบบจัดการกล้องผ่าน Web Dashboard (Camera Management)
   ─────────────────────────────────────────────────────────────────
   พัฒนาฟีเจอร์ให้ผู้ใช้สามารถเพิ่มและลบกล้องได้จากหน้า Dashboard
   โดยไม่ต้องแก้ไขโค้ดหรือรีสตาร์ท Server

   - สร้าง CameraManagerModal.vue — Modal จัดการกล้องประกอบด้วย
       • รายการกล้องที่มีอยู่ แสดง id, ประเภท, toggle Flip และปุ่มลบ
       • ฟอร์มเพิ่มกล้องใหม่: ชื่อ, ประเภท (IP Camera / Webcam),
         URL หรือ Port number, toggle Flip ซ้าย-ขวา
   - เพิ่มปุ่ม "⚙ จัดการกล้อง" ในแถบ Controls ของ CameraView.vue
   - เมื่อเพิ่ม/ลบกล้อง → reload รายการกล้องอัตโนมัติ
     และ reset focusedCamId ถ้ากล้องที่ focus ถูกลบออก

2. เพิ่ม API Endpoints สำหรับจัดการกล้อง (api.py)
   ─────────────────────────────────────────────────────────────────
   - เพิ่ม cameras_config.json สำหรับเก็บ config กล้องแบบ persistent
     ระบบโหลดจากไฟล์นี้เมื่อ start server (fallback ไป default
     ถ้าไฟล์ไม่มีหรือ parse error)
   - เพิ่ม field flip ใน camera config
   - อัปเดต GET /cameras ให้คืน source และ flip ด้วย
   - เพิ่ม POST /cameras — สร้างกล้องใหม่ บันทึกลง JSON
     (สร้าง id อัตโนมัติ เช่น cam3, cam4)
   - เพิ่ม DELETE /cameras/{cam_id} — หยุด process และลบกล้อง
   - เพิ่ม PATCH /cameras/{cam_id}/flip — อัปเดต flip real-time
     พร้อม restart face process อัตโนมัติถ้ากำลังรันอยู่

3. ระบบ Flip ภาพกล้อง
   ─────────────────────────────────────────────────────────────────
   - แก้ให้ config.py อ่าน CAMERA_FLIP จาก environment variable
     (รองรับ "1", "true", "yes")
   - ส่ง env var CAMERA_FLIP ไปให้ main.py ตอน start face process
     เพื่อให้ flip frame ก่อนวาด overlay (bounding box, label)
     ทำให้ overlay ยังอยู่ถูกตำแหน่งหลัง flip
   - เมื่อ toggle flip บน Dashboard → PATCH API → restart process
     อัตโนมัติพร้อมค่า CAMERA_FLIP ใหม่

4. เปลี่ยน HourlyChart จาก Bar Chart เป็น Line Chart
   ─────────────────────────────────────────────────────────────────
   - เปลี่ยน Chart.js type จาก 'bar' เป็น 'line'
   - ลงทะเบียน LineController, LineElement, PointElement, Filler
   - เพิ่ม fill: true + gradient สีโปร่งใสใต้เส้นกราฟ
   - tension: 0.4 ทำให้เส้นโค้งมน
   - pointRadius: 3, pointHoverRadius: 5 แสดงจุดข้อมูลชัดเจน

5. เพิ่มระบบ Theme (Light / Dark / อัตโนมัติตามเวลา)
   ─────────────────────────────────────────────────────────────────
   ออกแบบและพัฒนาระบบ theme ที่เปลี่ยนสีทั้ง Dashboard ได้แบบ
   real-time โดยไม่ต้อง reload หน้า

   - ปรับ tailwind.config.js ให้สี gui-bg/panel/border/text/dim
     ใช้ CSS variable แทน hardcode (darkMode: 'class')
   - กำหนด CSS variable ใน style.css:
       :root       → Light theme (#f6f8fa background)
       html.dark   → Dark theme (#0d1117 background เหมือนเดิม)
   - สร้าง useTheme.js composable จัดการ theme state
     บันทึกใน localStorage และ apply ทันทีโดยไม่ต้อง reload
   - เพิ่ม inline script ใน index.html apply theme ก่อน Vue mount
     ป้องกัน flash of wrong theme
   - เพิ่มปุ่ม ☀ / 🌙 / 💻 ใน AppHeader สำหรับเลือก theme
   - Mode "ตามระบบ" ใช้เวลาจริงเป็นเกณฑ์:
       06:00–17:59 → Light theme (กลางวัน)
       18:00–05:59 → Dark theme  (กลางคืน)
     มี setInterval ทุก 60 วินาที สลับ theme อัตโนมัติเมื่อถึงเวลา
   - แก้ HourlyChart.vue ให้อ่านสีจาก CSS variable และ rebuild
     chart เมื่อ theme เปลี่ยน

■ ปัญหาที่พบและแนวทางแก้ไข
────────────────────────────────────────────────────────────────────────

  ปัญหา : Flip ภาพด้วย CSS scaleX(-1) บน <img> ทำให้ bounding box
           และ label ที่ main.py วาดบนเฟรมถูก mirror ตามไปด้วย
  วิเคราะห์: main.py วาด overlay หลัง CAMERA_FLIP → overlay อยู่ใน
              พิกัดที่ถูกต้องบนเฟรมที่ flip แล้ว ถ้า CSS flip ซ้ำ
              overlay จะถูก mirror สองครั้งแสดงผิดตำแหน่ง
  แก้ไข : ให้ main.py จัดการ flip ผ่าน CAMERA_FLIP env var ก่อนวาด
           overlay และ restart process เมื่อเปลี่ยน flip setting
           โดยไม่ใช้ CSS flip บน <img>

  ปัญหา : Vue watch() ที่ module level ไม่ trigger DOM manipulation
           ทำให้ theme ไม่เปลี่ยนแม้กดปุ่ม
  วิเคราะห์: watch() นอก component setup() อาจไม่ reliable ใน Vue 3
  แก้ไข : เปลี่ยนเป็น setTheme() function ที่เรียก applyTheme()
           ตรงๆ ทันทีเมื่อผู้ใช้กดปุ่ม

■ งานที่ดำเนินการในวันนี้
────────────────────────────────────────────────────────────────────────

1. เพิ่มระบบ Multi-Camera ใน api.py — รองรับกล้องหลายตัวพร้อมกัน
   ─────────────────────────────────────────────────────────────────
   ออกแบบและพัฒนาสถาปัตยกรรมใหม่ให้ api.py รองรับกล้องหลายตัวได้
   โดยแต่ละกล้องมี MJPEG stream, Face Recognition process และ
   state file เป็นของตัวเองอิสระ

   - เพิ่ม CAMERAS_CONFIG (list) สำหรับตั้งค่ากล้องทุกตัวในที่เดียว
     แต่ละรายการมี id, name, source (USB index หรือ RTSP URL)
   - รองรับ override ผ่าน environment variable (CAMERA1_URL, CAMERA2_URL)
   - เพิ่มฟังก์ชัน _parse_cam_source() แปลง string จาก env → int
     เมื่อเป็น USB index หรือคง string ไว้เมื่อเป็น RTSP URL

   REST API endpoints ที่เพิ่มใหม่:
     GET  /cameras                       — คืนรายการกล้องทั้งหมด
     GET  /cameras/{id}/stream           — MJPEG stream โดยตรง (ไม่มี overlay)
     GET  /cameras/{id}/face-stream      — MJPEG stream พร้อม face recognition overlay
     GET  /cameras/{id}/face/status      — สถานะ process + frame age
     POST /cameras/{id}/face/start       — start main.py สำหรับกล้องนั้น
     POST /cameras/{id}/face/stop        — stop main.py สำหรับกล้องนั้น

   - แต่ละกล้องใช้ live_frame_{cam_id}.jpg และ live_state_{cam_id}.json
     แยกกัน ป้องกัน race condition ระหว่างกล้อง
   - เพิ่ม helper _live_frame_path_for() และ _live_state_path_for()
     สร้าง path จาก cam_id อัตโนมัติ

2. อัปเดต /session/live ให้รวมข้อมูลจากทุกกล้อง
   ─────────────────────────────────────────────────────────────────
   /session/live เดิมอ่านจาก live_state.json ไฟล์เดียว
   แก้ให้อ่านจาก live_state_{cam_id}.json ของทุกกล้องแล้วรวม
   (merge) ผลลัพธ์ โดย:
   - รวม persons จากทุกกล้อง ไม่ซ้ำ per_id
   - active = True ถ้ามีกล้องอย่างน้อย 1 ตัวที่ยังรันอยู่
   - stale = True ถ้าข้อมูลทุกกล้องเก่าเกิน 5 วินาที
   - fallback ไปที่ live_state.json (legacy) เพื่อ backward compat

3. แก้ไข _open_camera() ให้เสถียรขึ้นสำหรับ USB และ RTSP
   ─────────────────────────────────────────────────────────────────
   - USB: ใช้ cv2.CAP_V4L2 บน Linux (เสถียรกว่า default backend)
     พร้อม fallback เป็น VideoCapture(source) ถ้า V4L2 ไม่พร้อม
   - RTSP/HTTP: ใช้ cv2.CAP_FFMPEG โดยตรง + TCP transport
     (ตั้ง rtsp_transport=tcp ลด packet loss)
   - เพิ่ม timeout จาก 8 → 12 วินาที ให้ IP camera มีเวลา connect มากขึ้น

4. อัปเดต main.py รองรับ per-camera path และ multi-process
   ─────────────────────────────────────────────────────────────────
   - run_camera() รับ parameter เพิ่ม 3 ตัว:
       • camera_source    — override source (แทน cfg.CAMERA_URL)
       • live_frame_path  — override path เขียน live_frame.jpg
       • live_state_path  — override path เขียน live_state.json
   - _write_live_frame() และ _write_live_state() รับ path=None
     เมื่อกำหนด path จะเขียนไปที่นั้น แทนค่า global default
   - _LIVE_STATE_PATH และ _LIVE_FRAME_PATH รองรับ override ผ่าน
     env var FACE_LIVE_STATE_PATH และ FACE_LIVE_FRAME_PATH
   - __main__ block: ถ้า cfg.CAMERAS_LIST มีกล้อง 2+ ตัว
     จะ spawn subprocess แยกต่อกล้อง พร้อมตั้ง env FACE_CAMERA_CHILD=1
     เพื่อป้องกัน recursive spawn
   - แก้ cam_src: รองรับ string "0" / "1" จาก env ให้แปลงเป็น int
     ก่อนส่งให้ ThreadedCamera

5. เพิ่ม CAMERAS_LIST ใน config.py
   ─────────────────────────────────────────────────────────────────
   - เพิ่ม CAMERAS_LIST = [...] สำหรับ multi-camera mode
     ปัจจุบันตั้งค่า 2 กล้อง:
       • cam1 — USB index 0 (Laptop webcam)
       • cam2 — RTSP IP Camera (rtsp://192.168.1.13:554/...)
   - ตั้ง CAMERAS_LIST = [] หรือ None เพื่อรันแบบกล้องเดียว (legacy)

6. สร้างหน้า SingleCameraView.vue — ดูกล้องตัวเดียวแบบ Detail
   ─────────────────────────────────────────────────────────────────
   สร้างไฟล์ใหม่ dashboard/src/views/SingleCameraView.vue
   เป็นหน้า dedicated สำหรับดูกล้องแต่ละตัวแบบเต็มรายละเอียด

   - Header bar: ชื่อกล้อง + status badge (LIVE/กำลังเริ่มต้น/ออฟไลน์)
                 ปุ่ม Start/Stop + ปุ่ม Fullscreen + ปุ่มกลับ
   - Stream area: แสดง MJPEG face-recognition stream ของกล้องนั้น
                  Offline state แสดง oval guide + ปุ่มเปิดกล้อง
                  Info bar แสดง PID, frame age, ประเภทกล้อง
   - Right panel (Normal mode):
       • LiveDetection component — สถานะ liveness real-time
       • สถานะกล้อง — status, ประเภท, frame ล่าสุด, PID
       • วิธีใช้ — คำแนะนำการใช้งาน
   - Fullscreen mode: แสดง LiveDetection panel ในโหมด kiosk
   - Polling สถานะกล้องทุก 2 วินาที (setInterval)
   - รองรับ keyboard shortcut F สำหรับ toggle fullscreen

7. เพิ่มปุ่ม "ดูหน้าเต็ม" ใน CameraView.vue และอัปเดต Router
   ─────────────────────────────────────────────────────────────────
   - เพิ่ม RouterLink ⛶ (top-right overlay) ในแต่ละ camera panel
     ใน CameraView.vue เพื่อ link ไปยัง SingleCameraView
   - เพิ่ม route camera-detail ใน router/index.js:
       path: /camera/:camId → component: SingleCameraView
     โดยไม่ใส่ meta.label เพื่อไม่ให้แสดงใน AppNav navigation
