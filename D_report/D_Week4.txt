■ งานที่ดำเนินการในวันนี้
────────────────────────────────────────────────────────────────────────

1. วิเคราะห์และแก้ไขปัญหารูปภาพไม่แสดงในหน้ารายชื่อวันนี้ (Dashboard)
   ─────────────────────────────────────────────────────────────────
   พบว่ารูปหน้าพนักงานในหน้า "รายชื่อวันนี้" ไม่แสดงผล ทั้งที่เมื่อวาน
   ยังทำงานได้ปกติ จึงทำการวิเคราะห์ทีละชั้นจนพบสาเหตุ 2 จุด

   สาเหตุที่ 1 — main.py ไม่บันทึกรูปทันทีหลัง check-in
     Dashboard V2 เพิ่ม PENDING state ทำให้พนักงานโผล่ในรายชื่อตั้งแต่
     กำลังสแกนอยู่ (ก่อน check-in) ในขณะที่ save_snapshots() เดิม
     ถูกเรียกเฉพาะตอน session จบหรือกด q เท่านั้น
     ทำให้ช่วง PENDING → IN ยังไม่มีไฟล์รูปบน disk เลย

     แก้ไข : เพิ่มการเรียก session.save_snapshots() ทันทีหลัง
              session.try_checkin() คืนค่า True ใน main.py

   สาเหตุที่ 2 — browser cache 404 + photoError ไม่ reset
     เมื่อ PersonCard โหลดรูปของคนที่ยัง PENDING → API คืน 404
     → photoError = true → แสดง avatar แทน
     แม้ check-in สำเร็จแล้วมีรูปแล้ว photoError ก็ยังค้างเป็น true
     อยู่ ทำให้ไม่โหลดรูปซ้ำ และแม้รีเซ็ต photoError แล้ว browser
     ก็ยังใช้ 404 ที่ cache ไว้อยู่ดี

     แก้ไข : เพิ่ม watch ตาม status ของ person ใน PersonCard.vue
              เมื่อ status เปลี่ยนเป็น IN จะ reset photoError และ
              เปลี่ยน URL เป็น /person-photo/{per_id}?t=<timestamp>
              เพื่อบังคับให้ browser ยิง request ใหม่ข้ามผ่าน cache

2. แก้ไขปัญหาเดียวกันใน CameraView Fullscreen Sidebar
   ─────────────────────────────────────────────────────────────────
   Sidebar รายชื่อในโหมด Fullscreen ใช้ /person-face/{per_id}
   และมี failedPhotos (reactive Set) สำหรับ track รูปที่โหลดไม่ได้
   ซึ่งมีปัญหาเดียวกัน คือเมื่อเพิ่ม per_id เข้า failedPhotos แล้ว
   ไม่มีกลไก reset เมื่อสถานะเปลี่ยนเป็น IN

   แก้ไข :
     • เพิ่ม watch(mergedPersons) ตรวจสอบทุก person ว่า status = IN
       และยังอยู่ใน failedPhotos หรือไม่ ถ้าใช่ให้ลบออกพร้อมกัน
     • เพิ่ม photoRetry Map สำหรับเก็บ timestamp ต่อ per_id
     • เพิ่มฟังก์ชัน photoSrc(pid) คืน URL พร้อม ?t=timestamp
       เพื่อ bypass browser 404 cache
     • เพิ่ม watch ใน import จาก vue (แก้ ReferenceError ที่ทำให้
       หน้า Dashboard แสดงผลเป็นหน้าว่าง)

    → เพิ่ม session.save_snapshots() หลัง try_checkin() คืน True

    → เพิ่ม photoBust ref สำหรับ cache-busting timestamp

    → เพิ่ม watch ตาม person.status เมื่อเป็น IN ให้ reset
      photoError และอัปเดต photoBust เป็น Date.now()

  [แก้ไข] dashboard/src/views/CameraView.vue
    → เพิ่ม watch ใน import จาก vue
    → เพิ่ม photoRetry ref (Map) สำหรับ cache-busting ต่อ per_id

    → เพิ่ม watch(mergedPersons) reset failedPhotos และอัปเดต
      photoRetry เมื่อ person.status เปลี่ยนเป็น IN
    → เปลี่ยน template ให้ใช้ photoSrc(p.per_id) แทน URL ตรงๆ

       • ซ้าย : กล้อง Face Recognition (flex-1 เต็มความสูง)
       • ขวา : sidebar รายชื่อวันนี้ (ความกว้าง 340px)
   - Sidebar ประกอบด้วย
       • Header  — ชื่อ "รายชื่อวันนี้" + จำนวนคน + dot LIVE
                   (แสดงเมื่อ main.py กำลังทำงาน)
       • Stats   — แถบ IN / OUT / ยังอยู่ แบบ 3 ช่อง
       • Legend  — สีของสถานะ ยังอยู่ / ออกแล้ว / กำลังตรวจ
       • รายการ  — status bar 3px + avatar/รูป + ชื่อ/หน่วยงาน
                   + เวลา IN และ OUT แบบ font mono
       • Footer  — วันที่ปัจจุบัน (ภาษาไทย พร้อมวันของสัปดาห์)
   - ข้อมูลดึงจาก mergedPersons (รวม live session + DB วันนี้)
     เรียงลำดับ IN → PENDING → OUT เหมือนหน้าหลัก Dashboard

2. เพิ่มรูป Face Crop (Bounding Box) สำหรับ Sidebar Fullscreen
   ─────────────────────────────────────────────────────────────────
   ก่อนหน้านี้รูปในการ์ดพนักงานใช้ภาพเต็ม frame (full frame snapshot)
   แก้ให้ Sidebar Fullscreen แสดงเฉพาะ bounding box ที่จับหน้า
   โดยเพิ่ม pipeline ตั้งแต่การเก็บข้อมูลจนถึงการแสดงผล ดังนี้

   - session_manager.py
       • เพิ่ม attribute snapshot_face = None ใน PersonState
       • เพิ่มการบันทึกไฟล์ HH-MM-SS_{per_id}_FACE.jpg
         ใน save_snapshots() แยกจาก _IN.jpg เดิม

   - main.py
       • เก็บ person.snapshot_face = crop.copy() ทันทีที่
         liveness confirmed และยังไม่ได้ check-in
         (crop คือ bounding box + padding 15px ที่ใช้อยู่แล้ว)

   - api.py
       • เพิ่ม endpoint GET /person-face/{per_id}
         ค้นหา _FACE.jpg ก่อน fallback เป็น _IN.jpg
         ถ้าไม่พบทั้งคู่คืน 404

   - CameraView.vue (Fullscreen sidebar)
       • เปลี่ยน src รูปจาก /person-photo/ เป็น /person-face/

1. แก้ไขปัญหา main.py หยุดทำงานเองโดยไม่ตั้งใจ
   ─────────────────────────────────────────────────────────────────
   เพิ่ม restart loop ใน __main__ ของ main.py เพื่อให้โปรแกรม
   รีสตาร์ทอัตโนมัติเมื่อเกิดข้อผิดพลาด (Exception) ใดๆ

2. รวมหน้า Camera และหน้าข้อมูลวันนี้เป็นหน้าเดียว
   ─────────────────────────────────────────────────────────────────
   - ย้ายเนื้อหาทั้งหมดของ DashboardView.vue เข้ารวมใน CameraView.vue
     โดยวางส่วนกล้องไว้ด้านบน และส่วนข้อมูลวันนี้ไว้ด้านล่าง
   - อัปเดต router/index.js ให้มีเพียง route เดียวที่ path "/"
     ซึ่ง AppNav จะแสดงเมนูเพียงรายการเดียวโดยอัตโนมัติ
   - นำเข้า composables ทั้ง useAttendance และ useLiveSession
     และ component StatCard, PersonCard, AttendanceFeed, HourlyChart,
     OrgBreakdown เข้ามาใน CameraView.vue ด้วย

3. ลบการแสดงแหล่งที่มาของกล้อง (Camera Source)
   ─────────────────────────────────────────────────────────────────

     • แถบ Controls ด้านล่างหน้าจอกล้อง
     • ส่วน "สถานะระบบ" ในแผงขวา (บล็อก "แหล่งกล้อง")
   รวมถึงลบ ref, constant และฟังก์ชัน fetchCameraInfo() ที่เกี่ยวข้องออก

4. เพิ่มฟีเจอร์ขยายหน้าจอกล้อง (Fullscreen)
   ─────────────────────────────────────────────────────────────────
   - เพิ่มปุ่ม "ขยาย / ย่อ" พร้อม hint ชื่อ shortcut [F]
     ในแถบ controls ด้านล่างหน้าจอกล้อง
   - เพิ่ม keyboard listener สำหรับกด F เพื่อ toggle fullscreen
     โดยไม่ทำงานเมื่อ focus อยู่ใน input หรือ textarea
   - ใช้ Browser Fullscreen API (requestFullscreen / exitFullscreen)

   - ติดตามสถานะ fullscreen ผ่าน fullscreenchange event
     เพื่ออัปเดตข้อความปุ่ม "ขยาย ↔ ย่อ" แบบ real-time
   - เพิ่ม CSS scoped สำหรับ layout เมื่ออยู่ในโหมด fullscreen
     ให้ภาพวิดีโอเต็มพื้นที่หน้าจอ
